Learn to write MilkDrop presets

Open Stims — it plays with nothing to install

A curriculum for going from "never seen a preset" to publishing your own — using Stims itself as the lab. Every example is a complete, working preset behind a ▶ Run link: it opens toil.fyi with the code loaded in the live editor. Nothing to install.

If you want the reference instead of the course, see the language reference and the pattern language in MILKDROP_CODING_GUIDE.md.

The path

All nine tracks are live. The plan that scoped them, plus ideas for what comes next (a technique cookbook, an in-editor reactivity meter, archive rescue), is in PRESET_AUTHORING_DOCS_PLAN.md.

How the examples work

Example sources live in examples/ as ordinary .milk files you can also import directly. Each ▶ Run link encodes the full file into the URL (#code=<base64>), so the link is the preset — share your own experiments the same way with the editor's Export or by copying the URL after an edit.

bun run check:authoring-examples compiles every example and verifies every run link matches its source file (--write on the underlying script regenerates them). CI treats a broken example like a broken build.

Conventions

  • Lessons show the one or two lines that changed; the linked file is always the complete preset.
  • Anything Stims-specific (rather than MilkDrop-standard) is flagged as such where it appears.
  • Techniques are credited to the authors who invented them. MilkDrop's culture is remix culture; the docs follow it.
