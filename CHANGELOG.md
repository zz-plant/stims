# Changelog

Notable changes to Stims, newest first, in the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. Each release's summary, with its engineering and performance results, is in the [release notes](./docs/RELEASE_NOTES.md); planned work is in the [roadmap](./docs/ROADMAP.md). `bun run release:notes -- --check` keeps the two files in step.

_Latest release: **v1.5.0**._

## [Unreleased]

### Added

- The README links a 20-second clip with sound, recorded through the Record panel by `scripts/generate-sound-clip.ts`. It and the workflow MP4 are served from `toil.fyi/clips/`: GitHub downloads an MP4 this size from a repository link instead of playing it, so the README's old link never played.
- `?room=1` turns a visit into a display nobody has to operate, for a sensory room, a waiting area or a projector. It skips the launch page and plays to the demo track, or to the room's microphone with `&audio=mic`. Reduce flashing is on. Each preset stays up for `&dwell=` seconds (30–3600, default 180) and gives way to the next with an eight-second dissolve. The page holds a wake lock, keeps drawing when the window loses focus, and hides the controls, preset names, notices and pointer. Keys and taps on the stage do nothing, including blackout and white flash, and nothing is saved. `?brightness=` and `?motion=` (0–1) lower the comfort settings for one visit on any link and never raise them above what the device has saved. Settings → Playback and audio → Room display builds the link, and `docs/guides/sensory-room.md` covers kiosk start-up (#1596).
- **Publish a public video link…** publishes a four-second silent clip of the running preset, with its source code, and returns a `/s/<id>` page whose Open Graph tags carry the clip, so chat apps that read `og:video` show a playable card. The browser uploads quantized frames and the preset code, never audio. The Worker encodes a GIF and a JPEG poster, converts the GIF once to an H.264 MP4 through Cloudflare's Media binding, and serves the MP4 from R2 with byte ranges; only a record with a finished MP4 gets `og:video`. Uploads are same-origin, bounded in bytes, frames, dimensions and duration, and limited to three per IP a minute. Share pages are `noindex,follow`, the recipient runs the published code from an inert payload on the same origin, and the dialog hands back a token that deletes the record and every media file. The home page and `?preset=shifter-curlique` carry a curated clip (19,007 bytes at 192×108) (#1555, #1572).
- More actions → Share link has an **Embed** button, and the palette has Copy embed code (`copy-embed-code`). Both copy an `<iframe>` for the playing preset (`?embed=true&preset=<id>` on the page's own origin, titled with the preset and its author, 800×450 and responsive, `loading="lazy"`); before, embedding needed the `?embed=true` flag, which no screen mentioned. The snippet never carries a draft, and with unsaved edits the button says so. A preset made or imported in this browser has no embed, because no other browser can load its id. The oEmbed provider builds its `html` from the same code, so its iframe gains the responsive style, `fullscreen` and lazy loading (#1584).
- The editor's code names the sounds that drive each field: a line that sets an audio-driven field ends in its sources, as in `zoom=0.999514 ← bass, mid, treb`, read from the same dataflow analysis as the Tune chips. A field's literal line is tagged, and so is the last assignment to it in the per-frame or per-pixel equations; an assignment a later one overwrites is not. A newly loaded preset scrolls to the first tagged line (line 208 on the first-run preset). Before, only the Tune chips made this claim, and on a first open two of 45 were on screen at 1280×720 and none at 390×844. The tags are `aria-hidden`; the chips keep the accessible list (#1587).
- Find a preset has a **By reference** mode. Describe a look, and Stims ranks editable starting presets on the device with Browse's text scorer and the EmbeddingGemma 2 visual-term vectors; the description is not uploaded. An optional reference image lets Clef Omni pick among up to 12 of the matches, or decline. Open one in the editor and mark it accepted or rejected: the outcome goes to a local IndexedDB store (at most 100 episodes and 32 MiB, oldest evicted first), and later searches can reuse an accepted reference (#1551, #1552).
- Telemetry records which actions run, and from which surface: `action:<id>` from `dock`, `menu`, `palette`, `key`, `gesture`, `pad`, `landing`, `browse`, `editor`, `settings`, `cue` or `other`, each counted once per page load and at most 150 per load. The id is the command-palette id, so `E` and the menu's Edit preset code both report `action:open-editor`, and an id outside the app's own pattern is not sent. The beacon carries only the context fields every beacon already has, the start page says "Usage is counted as anonymous events — no account", and `telemetry:report` adds an actions-by-surface table (#1552, #1581).
- Telemetry beacons carry the OS family (`android`, `ios`, `windows`, `macos`, `linux` or `other`), the browser engine (`chromium`, `webkit`, `gecko` or `other`), the engine's major version, and a flag for an Android WebView. The browser works these out and sends only the classes: no OS version, device model or browser name. Crash beacons no longer include the raw user-agent string, which the Worker never stored. `telemetry:report` adds audible starts by OS and device, and by engine major version.
- The agent verb `edit-source` (`run('edit-source', { source })` or `{ append }`) changes the preset code the way typing does: the session turns dirty, the edit is saved as the preset's draft, and the leave-page guard sees it, where `set-field` writes only the running VM. The result carries the editor state (`dirty`, `errorCount`, diagnostics), and `bun run ctl` waits for the engine before running it (#1593).
- `bun run live` acts on the tab a person is watching. Under `bun run dev`, the dev server's hot-reload socket relays commands to the visible, focused tab and writes its events, state and last capture to `scratch/live/`; saving `scratch/live/preset.milk` applies it as preset source, and saving `pattern.js` plays it as a Strudel pattern. The channel answers loopback only, is off for servers the lab and e2e scripts start, and leaves nothing in a production build. `.mcp.json` registers the `stims` MCP server for Claude Code (#1574).
- Agent-readiness surfaces on toil.fyi: robots.txt carries Content-Signal usage preferences (search and ai-input allowed, ai-train not declared as allowed) in every crawler group; every `/learn/` page has a markdown sibling served for its `.md` URL and for `Accept: text/markdown`, with `Content-Location` and `Vary: Accept`; HTML responses advertise the machine-readable surfaces (llms.txt, sitemap, OpenAPI, api-catalog, MCP card, skills index) in a Link header; and `/.well-known/api-catalog` (RFC 9727 linkset), `/.well-known/mcp/server-card.json` (it states that no MCP endpoint is hosted on this origin, replacing a card that pointed at a dead `/mcp`), `/auth.md` (no authentication required) and `/.well-known/agent-skills/` index two SKILL.md files for driving and embedding the visualizer. `check:seo` guards all of it (#1599).
- `bun run test:budget` ranks gate and package tests by the CPU they burn, subprocesses included, and predicts each test's wall time at a target load (default 4 × cores), so its verdict does not depend on how busy the machine is during the run; it exits 1 when a test on bun's 5 s default would overrun below that load. Firefox and WebKit get a first-run smoke e2e: the landing, the note that tab and YouTube audio need Chrome or Edge, and demo audio going live on WebGL (#1591, #1593).
- The offline embedding script takes `--dtype` (`fp32|fp16|q4|q4f16|q8`, default `q8`), so a full re-embedding pass can run the model repo's lower-precision weights. The image index records the dtype, and a dtype change must regenerate every derived artifact in the same pass (#1539).
- New docs: `PRODUCT.md` (who Stims is for, its positioning, and what no surface may claim), `docs/UPSTREAM_CONTRIBUTIONS.md` (every upstream PR and proposal, with its status) and `docs/LEARNING_LOOPS_SPEC.md` (the nine model-assisted learning loops, with their stores, review, privacy and release gates) (#1550, #1570, #1588).

- Two EEL rules follow the ns-eel2 source that MilkDrop 2 ships. `-2 ^ 2` is `-(2^2) = -4` on every tier (it was +4, the modern-EEL2 reading), and a `while()` condition counts as true only above the close factor (`|cond| > 1e-5`), so a condition that decays to 1e-6 ends the loop instead of running it to the iteration cap. No bundled preset writes `-a^b`, and all 558 `while()` statements in the corpus test a comparison or a logical result, so no bundled preset changes. All 82 `eel-conformance` cases are now pinned, and `packages/eel-conformance/docs/ns-eel2-source-audit.md` cites the file and construct behind each answer (#1567, #1595).
- Audio analysis allocates less per frame. Writing the audio texture the GPU reads takes 1.050 µs a frame instead of 2.921 µs (292.08 ms → 104.96 ms over 100,000 frames), because each pixel is one 32-bit write instead of four byte writes and three `Math` calls. The AudioWorklet reuses its six per-tick result objects and its transfer list, the main thread reuses its buffer lists for each worklet message, `getFrequencyFrame` returns one cached result per analyser instead of a new object every animation frame, and preset blends copy their typed arrays with `slice()`, about 35% faster in a benchmark (#1545, #1614).
- The audio analyser's FFT folds windowing, bit reversal and the first two radix-4 stages into one pass, harmonic/percussive separation takes its 7-frame and 9-bin medians through branchless selection networks, and the WebGL mesh transform computes its zoom and scale reciprocals once per frame unless the per-pixel code writes them (`d867a7941`).
- React Compiler 1.0 compiles the frontend through `react({ compiler: true })` in both Vite configs. Rewrites of the try/finally, dynamic-import and logical-assignment patterns that made whole files bail took it from 46 to 51 of the 59 files under `src/js/frontend/`; Browse, the stage dock and preset artwork followed, moving the strict census (every component and hook in a file compiles) from 48 of 61 to 51 of 62. The CDN serves the raw `application/octet-stream` binary uncompressed, so a first visual search downloaded 409 KB and now downloads 292 KB. `check:bundle-size` budgets the twin and checks that it round-trips to the raw file byte for byte (#1539).

### Security

- Shared links are bounded before they are decoded. A `#code=z1~` link was inflated with no cap on the first render, so a short payload could expand to hundreds of megabytes, and the preset-set decoder capped memory but not time. Both reject compressed input longer than any link Stims writes (16,000 bytes) and cap the decoded size at 1 MiB of preset source and 4 KB for a set (#1548, #1598).
- One frame's programs share a single budget of 2,097,152 loop iterations: the per-frame program, every per-pixel vertex, and every wave sample and shape instance together. The cap used to apply per call, so a `while(1)` in per-pixel code ran it at every mesh vertex, about 25 s of main-thread work per frame from one opened share link. The heaviest bundled preset needs 80,281 iterations a frame (`martin-city-of-shadows`), so none reaches the budget (#1598).
- Preset equations also run under a wall-clock ceiling. A step that has spent 50 ms stops its loops and skips the remaining per-vertex and per-sample calls; init programs get 500 ms instead of an unlimited shared budget, and `getExecutionBudgetExceeded()` reports a truncated step. Compilation, shader work and geometry still have their own costs, and the live render path still runs on the main thread; the generated-preset reactivity probe compiles and steps untrusted source in a terminable worker with a timeout (#1600).
- **Breaking for embedding pages:** the iframe bridge accepts commands from another site only when that site is the direct parent of an explicit embed (`?embed=true` or an alias). From such a page, `toil:run` runs only 15 reviewed visual actions (preset navigation, `select-preset`, `set-field`, `crossfade`, parameter pins, the preset lock, autoplay, transition mode and length, `toggle-blackout`); device, clipboard and sharing actions are refused with a reason, and `toil:set_audio` still starts demo or microphone audio. Messages from an opener, a sibling, no sender or an opaque origin are ignored, and replies go to the requesting origin instead of `*`. Same-origin tools keep the full action API (#1598, `d478166bb`).
- Development dependencies clear the advisories that failed `bun audit --audit-level=high`: happy-dom 21.0.4 (GHSA-834v-8h66-3h79), the undici override at ^7.30.1 (GHSA-xjj6-f33q-929c), and zod 4.6.6 (GHSA-mrhx-c7xc-m3w5) (#1549, #1556).

## [1.5.0] - 2026-10-21

### Added

- A Browse search made only of visual terms ("tunnel", "red fire", "ocean waves") also lists every preset whose preview looks like it. Presets whose title, author or tags name the term come first, then the rest in order of resemblance. The terms ship as EmbeddingGemma 2 vectors (`visual-terms.json`, 19 KB gzip) and are scored on the device against the preset preview vectors. Before, a term found only the presets the build had tagged with it, and two terms needed both tags on one preset: "tunnel" listed 7 presets and now lists 28; "red fire" listed none and now lists 6. A search with any other word is unchanged, and the preview vectors are fetched only for an all-visual search (#1529).
- `/presets/` lists every indexable preset, A–Z with its credit, and every collection and author page with its count. It is static HTML in the `/learn/` shell (`scripts/preset-index-page.ts`) (#1391).
- Each `/author/<slug>` and `/discover/<slug>` page lists every preset in its collection as links: in the raw HTML, written by the edge into `#app`, and below the stage once the app mounts (`CollectionPageDetails`). Long lists are grouped under letter headings with jump links. Before, the only list was Browse's, rendered client-side and virtualized, so a hub's raw HTML held no preset link and a rendering crawler saw 30 to 36 (#1391).
- Every page ends with a site index linking `/presets/` and every hub. The home page, the hubs and the preset pages carry it in their raw HTML, and the app renders it below the stage. It replaces a nav clipped to one pixel and marked `inert`, which listed six of the thirteen topic pages and no author page (#1391).
- A preset page links its `.milk` file ("Download .milk"), below the stage and in the `<noscript>` copy. `.milk` files carry `X-Robots-Tag: noindex`, so the page ranks for the preset rather than its source (#1391).
- Author pages for the 19 credited hands with 10 or more indexable presets and no page yet, from Royal (58) to ShadowHarlequin (10). A test fails when the catalog grows another (#1391).
- The Tune pane says which audio drives each control. When the preset's equations recompute a field, its chip names the signals that reach it (`eq · bass`, all of them in the tooltip and accessible name), or says no audio does. It reads the static dataflow analysis (`src/js/milkdrop/preset-dataflow.ts`) of the compile on stage. So it follows a signal through `q` variables, persistent state and per-pixel equations, works before any music plays, and reruns only when the equations change (`dataflowSignature()`), not on every fader move (#1329).
- A Tune fader whose field the per-frame code recomputes shows the value the frame used, as a tick on its track beside the base value the fader holds. ## [1.1.0] - 2026-07-19

1.1.0 is the first version recorded after 1.0.0, and covers the 20 months between them, in which 16 static HTML pages became a MilkDrop preset player. It, 1.2.0 and 1.3.0 were written up from history on 2026-07-29 and never set in `package.json` or tagged. Main's history was rewritten in October 2026 to drop `assets/` and `output/` from every commit, so commits before 2026-07-24 carry no app source; the SHAs below are main's, and two changes with no copy on main carry none.

### Added

- A buildable project (June 2025): a `package.json` with Jest tests (#19), a Vite build that bundles three.js from npm instead of cdnjs (#63), TypeScript (#67, #69), and one `toy.html?toy=<id>` loader in place of per-toy pages (#68).
- Bun and Cloudflare (December 2025): tests on Bun's runner with `bun.lock` and CI on Bun (#195, #223), a Cloudflare Pages build (`d3e1fff90`), and an MCP server for agents (`6e5af978b`, #243).
- The MilkDrop engine (March 16, 2026): a `.milk` parser, an EEL expression parser and evaluator, a compiler, a per-frame VM, a three.js renderer adapter, a formatter, and a CodeMirror editor that compiles in a Web Worker, with a catalog of 4 presets (`107dc17ce`). The same day, 26 toys were rewritten as `.milk` presets (`012b4693c`).
- WebGL and WebGPU renderer adapters and feedback managers (March 19, 2026; `cf4881431`).
- Parity measurement against projectM (March 28–31, 2026): a parity artifact manifest, imported projectM reference renders for diffing, catalog fidelity labels synced from measured parity, and the 37 projectM upstream test presets under `public/milkdrop-presets/libraries/projectm-upstream/` (`bb54ed222`, `63f45d4f2`, `29a03ee39`).
- A React workspace with an engine adapter and URL state (April 3, 2026; `f2ad4189a`), and REPL-style editing (`3a10cf07c`).
- Equations on the GPU (April–May 2026): a GPU VM runner and WGSL generator (`f0c73fa85`), WebGPU render bundles (`bf3b45a0e`), and an expression-to-TSL compiler that runs per-pixel equations in the WebGPU fragment shader.
- MCP tools for listing and searching presets and an agent session manager (May 17, 2026; `83bbc577a`, `77125ea82`).
- The EEL JIT (May 29, 2026): expression trees compile to JavaScript functions in `expression-jit.ts` (`c09e9fe2e`).
- 1,748 Butterchurn presets imported, taking the catalog from 43 to 1,791 entries (May 30, 2026; `5def9c431`), and Cloudflare Functions for AI preset generation, D1 and R2 (`60a1d42c6`).
- MilkDrop 2 shader passes on WebGL (June 14, 2026): warp and composite are separate passes, with `sampler_fc_main` reading the warp output, and `sampler_blur1`–`sampler_blur3` read blur targets at 1×, 0.5× and 0.25× the feedback resolution.
- Performance controls with a persistent pixel ratio, a particle budget and shader-quality presets (`fc2a29f23`), and `useEngineSnapshot()` for frame-accurate engine state without re-rendering the whole UI tree (`4baa29dae`).
- Native projectM 3.1.12 reference renders: a C++/SDL harness linked against libprojectM renders the frames parity captures are compared with (`70200ac1c`), and `250-wavecode` is certified on WebGPU (mismatch ratio 0.0023); of the four shipped presets, one is WebGL-only and three remain uncertified (`1e292efa9`).

### Changed

- Biome replaced ESLint and Prettier (#395), three.js is imported by name, including its WebGPU entry points (`21c8b42a8`), and toys share one `createToyRuntime` (#443) (January 2026). Every toy was flagged WebGPU-first with a WebGL fallback (#757).
- The 26 alias-pack presets were replaced with curated ones (#884), and "toy" routes and copy gave way to `/milkdrop/` as the canonical route (#948).
- The workspace view split into `AudioSourcePanel`, `BrowseSheetPanel` and `SettingsSheetPanel` (`715fb1b80`).
- Theme and launch-screen rules moved out of `app-shell.css` into `shell-theme.css` and `shell-launch.css` (`93c1c15e2`).
- The light theme's muted text, line and accent colours are darker, dialogs, toasts and active controls are styled in light mode, and `prefers-contrast: more` and forced-colors mode have their own rules (`e988bdecd`).
- In live mode on narrow screens the stage fills the full dynamic viewport height with no padding or rounded corners, and the page stops scrolling.
- The VM reuses custom-wave objects across frames and writes mesh positions into one reused `Float32Array`.

### Removed

- The last loose HTML toys (`c7d2dc523`), 38 toy modules under `assets/js/toys/` (`cf4881431`), `toy.html` (#948), and the remaining bootstrap, loader, library-view and toy-view code, about 11,500 lines (`a96b7b092`).

### Fixed

- The 2D and volume noise textures use projectM's memory layout, in which Y (2D) and Z (volume) vary fastest (`f7b2896f5`).

## [1.0.0] - 2024-11-02

The `v1.0.0` tag was added on 2026-05-15, after the fact, on the last commit of the first stretch of work (2024-10-06 to 2024-11-02). The repository had no `package.json`, build step or tests. The October 2026 history rewrite removed `assets/` from that commit too, so `lights.html`, the one page that loaded `assets/js/app.js`, no longer runs from the tag.

### Added

- A static site of 16 standalone HTML pages, most reacting to microphone input, and an index linking 10 of them: 3D Toy, Star Guitar Visualizer, Defrag Visualizer, Evolutionary Weirdcore, Multi-Capability Visualizer, Trippy Synesthetic Visualizer, Pattern Recognition Visualizer, SVG + Three.js Visualizer, Dreamy Spectrograph and Interactive Word Cloud.
- Pages load three.js from cdnjs (r128 to r152, and the 0.169.0 `three.webgpu` build) or draw with raw WebGL, WebGPU or Canvas 2D. The Multi-Capability Visualizer tries WebGPU and falls back to WebGL.
