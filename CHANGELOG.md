# Changelog

All notable changes to this project will be documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

_Current release status: actively developed. Latest release: **v1.5.0**._

## [Unreleased]

### Planned — studio first, parity as a floor

- **Remix studio**: dependable undo/redo and named snapshots, side-by-side A/B against the source preset, remix provenance retained in exported `.milk`.
- **Creator-grade export**: deterministic frame pacing, loop-duration controls, and codec/AV-sync verification for 1080p and 4K recording.
- Parity stays a maintenance floor, not a frontier: projectM WebGPU compute-shader lowering and the AudioWorklet analyzer migration proceed only as they serve the compatibility labels and recording path above.

## [1.5.0] - 2026-10-21

### Added

- A Browse search made only of visual terms ("tunnel", "red fire", "ocean waves") also lists every preset whose preview looks like it. Presets whose title, author or tags name the term come first, then the rest in order of resemblance. The terms ship as EmbeddingGemma 2 vectors (`visual-terms.json`, 19 KB gzip) and are scored on the device against the preset preview vectors. Before, a term found only the presets the build had tagged with it, and two terms needed both tags on one preset: "tunnel" listed 7 presets and now lists 28; "red fire" listed none and now lists 6. A search with any other word is unchanged, and the preview vectors are fetched only for an all-visual search.
- `/presets/` lists every indexable preset, A–Z with its credit, and every collection and author page with its count. It is static HTML in the `/learn/` shell (`scripts/preset-index-page.ts`).
- Each `/author/<slug>` and `/discover/<slug>` page lists every preset in its collection as links: in the raw HTML, written by the edge into `#app`, and below the stage once the app mounts (`CollectionPageDetails`). Long lists are grouped under letter headings with jump links. Before, the only list was Browse's, rendered client-side and virtualized, so a hub's raw HTML held no preset link and a rendering crawler saw 30 to 36.
- Every page ends with a site index linking `/presets/` and every hub. The home page, the hubs and the preset pages carry it in their raw HTML, and the app renders it below the stage. It replaces a nav clipped to one pixel and marked `inert`, which listed six of the thirteen topic pages and no author page.
- A preset page links its `.milk` file ("Download .milk"), below the stage and in the `<noscript>` copy. `.milk` files carry `X-Robots-Tag: noindex`, so the page ranks for the preset rather than its source.
- Author pages for the 19 credited hands with 10 or more indexable presets and no page yet, from Royal (58) to ShadowHarlequin (10). A test fails when the catalog grows another.
- The Tune pane says which audio drives each control. When the preset's equations recompute a field, its chip names the signals that reach it (`eq · bass`, all of them in the tooltip and accessible name), or says no audio does. It reads the static dataflow analysis (`src/js/milkdrop/preset-dataflow.ts`) of the compile on stage. So it follows a signal through `q` variables, persistent state and per-pixel equations, works before any music plays, and reruns only when the equations change (`dataflowSignature()`), not on every fader move.
- A Tune fader whose field the per-frame code recomputes shows the value the frame used, as a tick on its track beside the base value the fader holds. The tick follows the running preset only while Tune is on screen and some fader has a tick. A field per-pixel code varies across the mesh gets none, since no single number is what was drawn.
- Outline rows say which audio reaches what each drawn part draws: the per-pixel equations and every enabled custom wave and shape (`bass +1`, or `no audio`). The answer comes from the same dataflow analysis as the Tune chips. A wave whose code reads no audio makes no claim, because its points sit on the waveform unless its code moves them.
- Solo and Mute in the Outline now cover the main waveform, the borders and the motion vectors as well as custom waves and shapes. Each layer gets a row under Settings when the preset draws it, at a visible base value or through an equation. Soloing any element now hides those layers too, so what remains is that element over the warped feedback.
- Each custom wave and shape has its own controls in Tune. Pick one in the pane's wave-or-shape picker, or press Tune on its Outline row. Its switches (draw, additive, thick, textured or spectrum and dots), colours and faders (sides, radius, position and angle; samples, scaling and smoothing) use the same widgets as the rest of the pane, and each move is a line in the draft. The `eq` chip on each control reads that slot's own code, so `x = …` in `shape_1_per_frame1` marks shape_1's X as recomputed. A field is found under whichever spelling the preset uses (`wavecode_0_bDrawThick` or `wavecode_0_thick`), and its own line is rewritten rather than a second one added.
- MCP tool `get_audio_reactivity_guide` (stdio and Worker) explains how presets read `bass`/`mid`/`treb`, their `_att` versions and `vol`, and names the `lab:dataflow` and `lab:reactivity` commands that check a preset. Given a `presetId`, it adds that preset's audio reach and measured reactivity from the catalog. `docs/ARCHITECTURE.md` and the authoring reference and listening chapter are now readable through `read_doc_section`.
- The iframe `postMessage` bridge answers truthfully. Every `toil:*` command gets one `toil:status` reply with `action`, `success` and a `reason` when it fails, echoes any `requestId`, and goes to the frame that asked. `toil:set_audio` and `toil:apply_tweak` do what they say (both replied success and did nothing), `toil:load_preset` replies once the stage shows the preset and refuses an unknown id with suggestions, and `toil:run` runs any palette action or agent verb. `bun run ctl -- --embed --post '<json>'` checks the protocol the way an embedding site sees it (#1328, #1332, #1334).
- The stage dock has an Edit this visual button beside the transport; the editor sat behind the More actions menu. First-time editors get one reversible example edit, a slow spin added after the preset's last equation. A Star Stims on GitHub note appears only after a successful share or video save, and stays dismissed once dismissed (#1342).
- Where Chrome offers WebGPU only in compatibility mode (an OpenGL ES backend), Stims uses it rather than falling back to WebGL. The GPU timestamp profiler and the compute VM stay off on that adapter (#1354).
- Browse cards and rows have a queue toggle beside the save heart, so the queue can line up presets that have not played yet; the dock and the palette could queue only the preset on stage (#1373).
- Four parts of Stims are standalone packages under `packages/`: `milkdrop-toolchain` (parser, EEL2 interpreter and JIT, IR, shader translation, formatter, MilkDrop 2 exporter, dataflow analysis), `flash-guard` (the WCAG 2.3.1 flash analysis and the live governor), `audio-reactive` (the AudioWorklet FFT, harmonic/percussive separation and beat tracking) and `eel-conformance` (the expression-language cases and a runner). The app imports them as Bun workspaces with no build step and no second copy of the code. Each has a read-only mirror repository and a demo site under `https://zz-plant.github.io/stims/`. `eel-conformance`, `flash-guard` and `milkdrop-toolchain` are published on npm; `audio-reactive` stays a workspace package (#1384, #1385, #1387, #1389, #1446).
- Share links carry remix lineage (`remix_of_N_id`, `_title`, `_author`), the same fields an exported `.milk` file carries, so credit survives a link as it survives a file. A source too long for a plain link is compressed (a `z1~` deflate-raw payload): every bundled preset now fits in a share link, where 16.8% did not. Links that fit before are byte-identical and old links decode as before (#1403).
- Generated presets are checked by the real compiler: `/api/validate-preset` runs `compileMilkdropPresetSource` instead of counting parentheses, with the same response shape. OpenRouter is a generation provider with a key you supply, sent from the browser to openrouter.ai and never through a Stims Worker. A generated preset that compiles but renders near-black is labelled low-confidence and offers Regenerate (#1404).
- The editor treats a preset's warp and composite shaders as their own blocks. Shader lines are highlighted, a shader that fails to compile reports its backend, program and stage instead of a bare fallback flag, and a Shader tab lists the blocks with jump-to-line, the compile errors (counted on the tab), and the GLSL the GPU runs (#1405).
- A watcher HUD (palette action `toggle-watcher-hud`) plots pinned variables over the stage, with the editor open or closed. Comparing two versions adds a summary of what the edit did to the audio reach, such as "zoom stopped listening to bass". A Textures tab lists the preset's texture bindings with a preview of each file it resolves to (#1406).
- The start page offers Edit this one beside Play demo and Browse presets once the preview is live; the folded dock keeps its own Edit button; the code gets at least eight lines above the dock; and a Tune chip names every band that drives its field (`eq · bass, mid, treb`), not only the first (#1406).
- Local audio takes several files at once, picked or dropped, and plays them as a playlist that advances at the end of each track and starts over after the last. Previous track and Next track appear in the audio panel and the dock's audio menu, the dock reads `File · 2/9`, and the system media keys and media controls follow the playlist. Palette actions: `next-audio-track`, `prev-audio-track` (#1443).
- `?reduceFlashing=1` turns Reduce flashing on for one visit, for a shared screen whose viewers never open Settings: shuffle and autoplay skip measured flashers and the live governor dims flashes. The setting saved on the device is unchanged, `?reduceFlashing=0` is ignored so no link can turn protection off, and the in-app toggle still wins (#1444).
- Two live stage keys for performing: D blacks out the picture while held, and two quick taps keep it black until the next press; Y flashes the screen white while held, so tapping strobes. Both change only what is shown, never the preset, its equations or the audio, and a notice beside the stage says how to bring the picture back. The shortcut list shows them under Live stage utilities (#1455).
- Nearby and the finder's By look tab rank presets by embeddings of their rendered previews (EmbeddingGemma 2, 256 int8 values per preset, fetched the first time a feature needs them). The old frame description gave most presets one of 81 descriptions, so most neighbours were ties. Browse can sort by Like your saved. 366 presets gained visual search terms ("tunnel", "galaxy", …), and Browse search now reads them: no catalog projection had passed `searchTerms` to the client, and "galaxy" now finds 12 presets instead of 3 (#1447).
- A per-preset frame-cost record, `src/data/preset-frame-cost.json`, filled by `lab:cost-ingest` from `perf:certification-corpus` runs and validated by `check:preset-cost`. On low-tier devices, autoplay and shuffle skip presets measured above 12 ms of frame work. The 43 presets measured so far ran on a high-end machine and none exceeds that budget, so nothing is skipped until low-tier measurements land (#1419).

### Fixed

- The first "Check animation (Clef Omni)" after a page load no longer reports "No animation frames were recorded." The first MediaRecorder a page creates can hand back an empty file — the encoder pipeline is not warm yet, so every frame is dropped — and the recording now retries once on exactly that outcome. This was the deterministic failure that had kept the `decision-workflows` e2e (and with it main's CI) red since #1536 landed.

### Changed

- The toolchain floor is Bun 1.4.3 (`.bun-version`, `engines.bun`, README), which the repo was already effectively on for `bun test --parallel`; 1.4 adds `bun audit fix`, `bun dedupe` and `bun prune` for the dependency-hygiene steps, plus `--cpu-prof-md` for profiling the measurement scripts from a terminal.
- React Compiler 1.0 compiles the frontend components through `react({ compiler: true })` in both Vite configs. 46 of the 59 files under `src/js/frontend/` compile today; the rest bail and are left untouched by design. Two files were rewritten to unblock whole files (`App.tsx`, `StageWarpGizmo.tsx`: logical assignment operators are not lowered yet, and one unparsable function skips the file). The heavy re-render sources — `App.tsx`, `BrowseSheetPanel.tsx`, `PresetFinderPanel.tsx` — still bail on refs-during-render, try/finally and dynamic-import patterns; shrinking those is the remaining adoption work.
- The visual search vectors ship a gzip twin, `visual-vectors.bin.gz` (292 KB, built in the same run as the raw binary). The loader decompresses it with `DecompressionStream` and falls back to the raw file. The raw binary is `application/octet-stream`, which the CDN serves uncompressed, so a first visual search downloaded 409 KB and now downloads 292 KB. `check:bundle-size` budgets the twin and verifies it round-trips to the raw file byte for byte.
- The offline embedding script takes `--dtype` (`fp32|fp16|q4|q4f16|q8`, default `q8`), so a full re-embedding pass can run the model repo's lower-precision weights instead of waiting on q8. The image index records the dtype, and a dtype change must regenerate every derived artifact in the same pass.
- The start page paints its headline and tagline from the HTML instead of waiting for the app bundle. On a bare `/` with no saved session, the boot cover carries the first-visit header where the launch column draws it, so the crossfade to the app moves no line. Other arrivals keep the plain wordmark cover, because their header differs. In Lighthouse's mobile run of a local production build, the start page's largest contentful paint fell from 4.8 s to 2.7 s.
- A `?preset=` or `?audio=` arrival mounts the engine once the launch page has painted. The engine's chunks (about 300 kB gzipped on WebGL) used to start downloading alongside that page's own and slow it. `check:bundle-size` now also fails a build that puts three.js on the eager path.
- The sitemap, `/presets/`, the hub lists and the related links all read one catalog table, `public/preset-meta.json`, built from the root catalog and every library. The sitemap used to read the root catalog alone, so 144 library presets linked from preset pages were missing from it and 72 sitemap presets had no inbound link. It now lists 2,488 presets, each linked from `/presets/`; it listed 1,787.
- 53 presets named only by a number ("11", "124") and the 37 projectM test fixtures ("000 Empty") stay playable and listed, but carry `noindex` and are left out of the sitemap. No catalog field names the numbered ones; their generated descriptions repeat ("dominant monochrome orange, smooth gradients, moderate motion").
- A preset with the same name and credit as an earlier one names that one as canonical and is left out of the sitemap. 72 library presets repeat a root preset this way, re-encoded with a version header.
- Every public surface now tells the same story about what Stims is and what is new in it. [`docs/LINEAGE_AND_CREDITS.md`](./docs/LINEAGE_AND_CREDITS.md#what-stims-contributes) states the three contributions: per-pixel equations on the GPU, held to the CPU's answer by differential fuzzing; fidelity measured against native projectM; and the preset corpus analysed as programs. The README, both `llms` files and the comparison page repeat them. Running presets in a browser (Butterchurn was first) and editing them live (MilkDrop 2 had an editor) are no longer presented as new.
- `llms.txt` and `llms-full.txt` drop the "high-performance" and AI-first framing, the `?tweak=` flag and `toil:apply_tweak` message (neither does anything), and catalog fields that do not exist; the model-backed API routes are marked optional. The home screen's tagline names MilkDrop, the MCP endpoint stops calling itself "Stim Webtoys", and "MilkDrop-inspired" is gone from the docs.
- The compiler case study is deleted: its IR type, JIT output and WGSL kernel were invented, it described a dead-store pass that does not exist, and it credited the browser MilkDrop to a WebAssembly projectM port instead of Butterchurn. Its accurate parts are in [`docs/TECHNICAL_ACHIEVEMENTS.md`](./docs/TECHNICAL_ACHIEVEMENTS.md), which also now says the per-frame compute VM is off by default and documents the corpus analysis.
- The start page's tagline and explainer say what you can do with a preset: play it, see what moves it, and change it while it plays. `/learn/milkdrop-online/` drops "Winamp's Visualizer in Your Browser" from its title, which `docs/LINEAGE_AND_CREDITS.md` asks public copy to avoid, and the agent instructions under `.github/` drop "MilkDrop-inspired".
- Docs pages no longer open by narrating themselves: sentences like "This document describes…" are removed where the title, outline, or a table's header row already says it (24 pages across `docs/` and `CONTRIBUTING.md`); where an opener mixed narration with substance, the substance stays. The rule is recorded in `docs/DOCS_MAINTENANCE.md`.
- Stims is set in Archivo and Martian Mono instead of IBM Plex. Each preset title on the stage gets its own width, from 62% to 112%, so it sets on one line, and wraps to two balanced lines only when it is too long fully condensed. The Learn pages load the same faces; they named a font they never loaded (#1358).
- One name per feature across the app (watch party, Find a preset, Demo audio), after a copy-edit of every user-visible string. The Learn course taught some wrong numbers: its smoothing examples barely reacted, the Track 3 beat flash never fired, and `sin(rad*12)` draws about two rings, not twelve. Those lessons are corrected (#1356, #1367).
- The first paint downloads 585 kB of JavaScript instead of 1,007 kB: the CodeMirror editor and `three/webgpu` no longer ride the boot path, and WebGL sessions never download `three/webgpu`. `check:bundle-size` fails a build that puts either back (#1357).
- WebGL batches shapes and borders as WebGPU does, which halves frame time on shape-heavy presets (`martin-the-bridge-of-khazad-dum` 4.49 → 2.30 ms on an M1 Max). Overlapping shapes of different kinds can draw in a different order, as they already did on WebGPU (#1355).
- The start page leads with what Stims is ("A music visualizer you can open up"), with Stims as a nameplate. Audio sources are one chip row, Browse presets is the same secondary button for first-time and returning visitors, and the demo note sits under Play demo. After Play, the first hint waits for the title card to clear, and the audio-match suggestion waits 12 s and is never offered for demo audio. Curated first now weighs how readable each preset's preview is, so it no longer opens with near-black thumbnails (#1368).
- The first-run preset is `shifter-curlique`. Its predecessor, `krash-rovastar-cerebral-demons-stars`, hard-codes a 16:9 warp centre, so on a phone held upright its stage settled to black on WebGPU. First-run evidence is now recorded at 1280×720 and 390×844 on both backends (#1376).
- Flash samples are read back in a worker, so Reduce flashing no longer holds the main thread for 2–3.6 ms a frame waiting on the GPU (#1375).
- Telemetry beacons carry coarse context: screen orientation, device class (phone, tablet or desktop), the live audio source, and an arrival class (search, assistant, social, internal, other or none) read from the referrer's hostname. The URL, its query and the hostname itself are never sent. Automated browsers (`navigator.webdriver`) no longer post telemetry (#1377, #1381).
- Preset switches on WebGPU compile the incoming preset's pipelines before the blend starts, holding the fade for up to 1.5 s while the old preset keeps playing. The 0.25–1 s freezes at a switch are gone; a 50–75 ms hitch mid-blend remains (#1422).
- Less CPU per frame: the JIT advances the EEL random generator inline and reads a variable used twice in one statement once (median frame work on `shifter-glassworms-flare` 5.24 → 4.51 ms), the per-vertex loop skips built-ins the per-pixel program never references (`eos-apocalypse` 4.14 → 3.77 ms), presets with an identity warp skip the mesh transform, and the preset fading out of a crossfade runs at 75% detail (#1420, #1421, #1424).
- Author pages say "MilkDrop presets credited to Royal. Each one plays live in your browser." instead of attaching "playing live" to the author's name, and the `/presets/` intro leads with the same phrase rather than trailing it after a list (#1395).

  - `launch_toy` → `open_preset_url`; pass `baseUrl` to target a local dev server.
  - `get_toy_audio_reactivity_guide` → `get_audio_reactivity_guide`.
  - `describe_loader` → `read_doc_section` on `docs/ARCHITECTURE.md` ("App bootstrap").
  - `capture_toy_screenshot`, `test_toy_interactivity`, `get_toy_health` (stdio only) → `capture_preset`, which now lists the page's console errors on success and on failure.
- `src/data/toys.json`, which nothing reads once those tools are gone. The sitemap's MilkDrop image title is now a constant in `scripts/generate-seo.ts`, and the Vite build no longer derives inputs from it.

### Fixed

- A shared preset's social card (`/api/og-preset`) is now a JPEG under 300KB: 96KB median across a quarter of the corpus, 296KB at worst. It was resvg's truecolor PNG, 775KB to 789KB for the presets checked in production, past the size at which WhatsApp, among others, drops the preview image. A 256-colour palette PNG, which keeps the static cards under the same limit, fit only by cutting the busiest 9% of frames to 64 or 32 colours, which darkened them visibly. Preset pages drop the shell's `og:image:type` (`image/png`), since the card URL answers with a JPEG or, when rendering fails, the static PNG; cards cached as PNG are not served again.
- On desktops with classic scrollbars, the launch column no longer slides sideways when the boot cover hands off to the app. The launch page scrolls, so its scrollbar appeared when React mounted while the cover had none: the column moved 7.5px at 1440px and the tagline lost 15px of measure at 412px (3px and 6px where the 6px custom scrollbar applies). The cover now reserves the same gutter, and the home view keeps base.css's stable gutter; live mode and embeds still drop it. `tests/e2e/chrome-visual-contract.test.ts` checks the hand-off with classic scrollbars as well as hidden ones.
- A `?preset=` page keeps the preset's name and "Starting with demo audio…" on screen until the session it started ends. It dropped to the generic first-visit pitch on the first render after auto-start, so the pitch showed during the engine boot and again under the stage's fade-in. That late paint was the page's largest contentful paint: 7.8 s in Lighthouse's mobile run, 5.5 s now.
- The crawl copy in the raw HTML's `#app`, the site index footer and a hub's preset list, is not laid out while the boot cover is up. React replaces it on mount, but under the cover it reflowed when the deferred stylesheets landed: a layout shift of 0.2–0.5 on the desktop home page and 0.24 on a hub page that no one could see.
- The artwork in a `?preset=` page's header no longer pushes the buttons and the demo note down when the catalog resolves the preset. Its box is held from the first render, which takes the page's layout shift from 0.09 to 0.
- A `?preset=` page names its preset. Below the stage, in normal flow, it shows the preset's name as the page's one h1, its author (linked to the author page where one exists), more presets by the same author, and the topic hubs. Search engines render the page and skip `<noscript>`, which held the only copy of this content, so the sitemap's preset URLs read as one page under the heading "Stims visualizer". The edge now writes its no-JavaScript copy into one `<noscript>` instead of all four in the shell, and both copies come from `functions/shared/preset-page.ts`.
- `/author/<slug>` and `/discover/<slug>` pages name their collection in the h1 ("Geiss MilkDrop Presets") instead of the home page's headline, for returning visitors too.
- Presets in Browse (grid tiles, list rows, the recently-played rail and the remix family) are links to their `?preset=` pages, so crawlers on the hub pages can follow them and a preset opens in a new tab with a modifier click. A plain click still switches presets in place.
- A preset credited to a chain such as "Stahlregen + Geiss" links each hand in its byline to that hand's author page. Its related presets come in one group per hand, drawn from the presets crediting that hand, the rule the author pages already use.
- Stims boots where reading `localStorage` throws: sandboxed iframes, third-party iframes under an opaque-origin parent (which covers the `?embed=true` player), and browsers that block site data. It used to stop at "Stims crashed" (#1330).
- A ramp taken over by a later ramp ends at once with `landing: 'superseded'` and names the targets it lost, instead of running out its duration and reporting values it never reached. MCP `session_ramp`, macros and scene recall move on accordingly (#1362).
- The skip link on `/certify/` appears on keyboard focus; its reveal rule was invalid inline CSS (#1363).
- Editing and comparing no longer overwrite work. Undo history restarts on each preset load (undo on a fresh editor used to empty the code). A/B compares your edit with the original rather than with itself. Reset is now Revert to the original, and it can be undone. Drafts are saved only for real edits, so later fixes to a `.milk` file reach visitors who had opened it. Refine shows a diff with Apply and Discard instead of replacing the running preset (#1369).
- Reduce flashing acts in production. The flash sampler read the canvas outside the task that drew it, so it saw a blank frame on WebGPU and a dimmer one on WebGL, and the governor never engaged outside agent mode. It now samples each frame as it is drawn, at a 60 Hz cadence; shuffle and autoplay skip measured flashers when it is on; the stage says "Dimming flashes" while it dims; and the setting is also in the dock menu and the command palette (#1370).
- The flash governor counts what the WCAG audit counts. It measures each tile instead of one bilinear sample, no longer reads its own dimming as content, and judges frames it skipped correctly. On the first-run preset both now count no flashes, so the stage stays at full brightness in silence (#1383).
- Links to presets you made or imported carry their code (`#code=`), so the recipient no longer gets "could not be loaded", and the receiving page imports the code as a preset of its own. Exported remixes record their parents (`remix_of_N_id`, `_title`, `_author`), and import reads them back (#1371).
- A MIDI fader bound to `crossfade` drives the cue deck's hand fade, DJ-style, instead of writing a `crossfade=` line into the preset. Knob moves write the running preset live and commit to the source once the control rests for 250 ms; every message used to recompile. Learned controls span each target's usable range instead of 0–1, and touching a Perform fader or the on-stage crossfade picks it as the learn target, as the Settings hint promised (#1372).
- Browse's Best match sort ranks by the search; it fell through to the unsorted order. "High fidelity first" is gone, since every bundled preset reported the same value for it (#1373).
- `/discover/<slug>` and `/author/<slug>` keep Browse open on their collection; an idle effect played the featured preset and closed the panel a second after it opened. A bare `/` stays `/` instead of becoming `/?preset=shifter-curlique`, and low-power and reduced-motion visitors keep the static landing (#1380).
- The stage names presets as their authors wrote them. A trailing `- <Name> Tweak` is read as the edit credit, so "Eo.S.+Phat Emergent factors - Bitcore Tweak" no longer shows as "Bitcore Tweak", and a title that opens with its own author chain drops the repeat (36 titles and 2 bylines in the catalog change). Filename underscores show as spaces. On phones, the title's shadow no longer clips into dark slabs, a two-line title drops one size, and at 480px and below the dock stacks the title over the byline (#1393).
- A shared `#code=` link waits for its preset to load before restoring the edited source. It could compile against a fallback preset while the requested one was loading and then lose the restored source or the hash (#1407).
- The boot cover and the home hero reserve the same thin scrollbar gutter, so the tagline keeps its width when the app takes over; at 412px with classic scrollbars it narrowed from 369px to 359px (#1416).
- More preset shaders compile on WebGL. Native bodies have HLSL `saturate`, `frac`, `lerp` and `atan2` translated (65 shader stages reached GLSL with them) and assignments wrapped in the target's type, as HLSL broadcasts and truncates; comma-list and `static` declarations above `shader_body` carry over; a split `float3 dx, dy;` no longer turns `dx` into the motion control; and the warp shader declares the `r`/`g`/`b` and `hue_shader` colour uniforms it reads (#1448).

## [1.4.0] - 2026-10-01

### Added

- Pushing a `vX.Y.Z` tag publishes a GitHub Release: `.github/workflows/release.yml` runs `bun run release:notes`, which takes that version's section of `docs/RELEASE_NOTES.md` and refuses a tag that disagrees with `package.json` or has no notes. Versions 1.1.0 through 1.3.0 were written up but never tagged, so none of them appeared on the repo page.
- Pause. Space and the dock's transport button hold the picture and release it; the preset, history and audio session stay put. ## [1.3.0] - 2026-07-29

### Added

- Preset equations restored across the bundled butterchurn corpus. `scripts/butterchurn-eel-transpiler.ts` converts upstream JavaScript equation strings back to MilkDrop EEL, writing canonical `.milk` output (`per_frame_N`, `per_pixel_N`, `wave_N_per_pointM`, `shape_N_per_frameM`, `wavecode_N_*`, `shapecode_N_*`). 157,950 statements recovered; 1629 presets gained per-frame code and 1068 gained per-pixel code (1739 presets now compile clean).
- Custom shape instancing (`shapecode_N_num_inst`): per-frame shape code now runs once per instance with `instance` and `num_inst` in scope. 304 bundled presets declare multi-instance shapes and 232 vary geometry by `instance`.
- `randint`, `log10`, and `gmegabuf` functions added to the preset expression language engine.
- `EngineSnapshotCtx` with `useEngineSnapshot()` hook for frame-accurate state without re-rendering the full UI tree.
- Performance controls with persistent pixel ratio, particle budget, and shader-quality presets.

### Changed

- Console-style settings, browse drawer, and dock redesigned (`redesign(chrome): console-style settings, browse, and dock`).
- VM program blocks compile to one JavaScript function each instead of one per statement, reducing VM CPU cost from 2.00 ms/frame to 1.10 ms/frame.
- Compute VM readback buffer reuse and signal array packing optimized in WebGPU backend (`perf(webgpu)`).
- Fullscreen rendering quality and refresh targets optimized for mobile hardware (`perf(mobile)`).
- Centralized URL override handling and sanitized storage access helper (`refactor(core)`).
- Custom shape radius floor lowered from 0.04 to 0.002 so MilkDrop instanced dot fields remain accurately sized.

### Fixed

- Mesh transform cache removed: it quantized coordinates to 1/2048, so distinct points collided onto one key and a motion-vector point could receive a mesh vertex's transform from the opposite edge of the screen — four vectors per frame drawn ~2.0 NDC out of place. It served ~86 of ~24,320 transform calls per frame while every per-pixel preset paid a key computation, pool bump and `Map.set` on all ~1764 vertices (`fix(milkdrop)`).
- **Correction to `0eb14b23`:** that commit's message claims its per-vertex hoist was bit-exact. Later verification with fixtures that genuinely emit motion vectors found one branch — no per-pixel program, legacy `mv_dx`/`mv_dy`, direct path (≤288 cells) — where four vectors per frame differed. The change was in fact a partial *fix* for the cache-collision bug above rather than a no-op, and no shipped preset reached that branch (all 1,782 swept). The cache removal supersedes it.
- Enhanced microphone permission error guidance and fallback device error handling (`fix(audio)`).
- Microphone capture behavior repaired on mobile browsers (`fix(audio)`).
