# Page-level specifications

Detailed, testable requirements for the unified MilkDrop app route at `/` and the legacy alias at `/milkdrop/`.

For usage, see the [user guide](./USER_GUIDE.md). These are expected contracts, not a statement that every browser check is green. The mobile startup-cover width mismatch was fixed in [PR #1416](https://github.com/zz-plant/stims/pull/1416); browser coverage remains in `tests/e2e/chrome-visual-contract.test.ts`.

## Unified app route (`/` via `index.html`)

| Section | Expected data and state | Layout and interaction expectations | Accessibility and status behaviors |
| --- | --- | --- | --- |
| **Route behavior** | Loads shared styles from `src/css/base.css` and `src/css/index.css`, uses `lang="en"`, preserves the saved theme before paint, and keeps the `index.html` document active for the root URL. Query params like `audio=demo`, `panel=browse`, `panel=editor`, `collection=cream-of-the-crop`, and `preset=eos-glowsticks-v2-03-music` tune the initial state. Legacy links using `preset=signal-bloom` should resolve to the same featured preset. | The root URL is both the product surface and the session entry surface. It should not require a separate launch route for normal use. | Theme toggle must keep `aria-pressed` and `aria-label` in sync for any visible shell controls. |
| **Startup handoff** | The static `#stims-loading` screen is a sibling immediately before `#app`, so React's first root commit cannot remove it prematurely. The shell dismisses it only after reporting `shell-rendered`. On a bare `/` with no saved session the screen also carries the first-visit header (nameplate, headline, tagline), so the page's largest text paints from HTML. Every other arrival gets the wordmark alone, because its header differs. The crawl copy in `#app` (site index footer, hub preset list) is not laid out while the cover is up, so it cannot reflow beneath it. | The loader is laid out like the launch column and reserves the same scrollbar gutter (none for an embed), and `tests/e2e/chrome-visual-contract.test.ts` holds each line within 1px of where the React page draws it, with classic scrollbars and with hidden ones. The overlay then crossfades away instead of jumping from a centered spinner to a different layout. | The loader remains a live status region while startup phases change. Its copy of the header is `aria-hidden`; React's h1 is the one assistive technology reads. Dismissal marks it hidden to assistive technology; reduced-motion users skip the transition. |
| **Crawl links** | `#app` in the static shell holds the site index footer (`functions/shared/site-index.ts`, written by `bun run generate:seo`): `/`, `/presets/`, the learn pages, `/performance/` and every `/discover/` and `/author/` page. It never links `/milkdrop/`. On a hub route the edge adds the hub's full preset list ahead of it. | React replaces the contents of `#app` on mount with the same footer and list (`SiteIndexFooter`, `CollectionPageDetails`), below the stage, so the links are visible after JavaScript as well as in the raw HTML. | Real links, not `inert` and not clipped; `check:seo` fails when the footer is stale. |
| **Navigation and tools** | The React workspace owns navigation, the control dock, and browse, editor, and settings panels. | Opening a tool preserves the live preset and canonical URL state. Folded or inactive controls must not compete with the active controls. | Visible actions remain keyboard reachable; focus and panel dismissal follow the current workspace contracts. |
| **Intro block** | Static copy introduces the visualizer. The featured preset can render at entry; demo audio playback follows browser autoplay and user-gesture policy. | Short context block appears above the runtime controls. Play and audio controls must communicate the actual ready/playing state. | |
| **Audio controls** | `AudioSourcePanel.tsx` offers demo, microphone, file, tab capture, and YouTube. Chip or card layout depends on the host surface; a resume action can omit a duplicate source. Status communicates the actual ready or playing state and permission failures. | Source choices fit narrow widths. Picker-based sources retain their browser gesture and permission requirements. | Labels, visible focus, and status announcements remain available. IDs are instance-scoped because home and Settings can mount together. |
| **Quality controls** | Settings persist quality, compatibility mode, render scale, and pixel-ratio preferences to local storage. | Changing a setting updates the shared runtime preference rather than creating a parallel renderer. | Labels describe performance tradeoffs clearly. |
| **MilkDrop session** | After a successful start, the unified route owns the viewport and the shell collapses redundant controls aggressively. The active session keeps presets primary while the editor stays one layer deeper inside the overlay. | Session UI remains focused on one visualizer instead of pretending to browse multiple products, and visible chrome should feel minimal by default. | Runtime updates continue to reuse the status region so screen readers hear later errors. |

## Legacy alias (`/milkdrop/` via `milkdrop/index.html`)

| Section | Expected data and state | Layout and interaction expectations | Accessibility and status behaviors |
| --- | --- | --- | --- |
| **Alias behavior** | Loads a lightweight HTML document that preserves the current query string and hash and redirects to `/`. It is `noindex,follow` and canonicals to `https://toil.fyi/`. | Users and old links that open `/milkdrop/` should land in the same unified app route without losing launch intent. Search Console's "Alternate page with proper canonical tag" classification is intentional for this URL. | Redirect fallback link remains visible if scripting is unavailable. `bun run check:seo` verifies the alias canonical, noindex directive, and sitemap exclusion. |
