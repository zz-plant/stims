The part of a MilkDrop engine that never touches a GPU.

A TypeScript toolchain for .milk presets: a lossless parser, an EEL2 interpreter and JIT, an intermediate representation, HLSL analysis of the warp and composite shaders with GLSL emission, EEL-to-WGSL compute lowering, a formatter, exact MilkDrop 2 export, and dataflow analysis that reads which audio reaches which control. It keeps presets as .milk files, so anything it writes still opens in MilkDrop, projectM or Butterchurn. Born in Stims, where the same code compiles every preset the visualizer plays.

npm install milkdrop-toolchain Try it in the browser Read the README

Pipeline

Preset text goes through a lossless line tree, a field parser and the IR builder, which also parses every equation and classifies the shader text. From the IR, three execution tiers agree on one semantics, and the formatter and exporter turn it back into text.

What is not here

The package stops where the GPU starts. Four things a complete engine needs that live in the host instead.

The renderer

Drawing waves, shapes, the warp mesh and the composite pass, and feeding audio into the signal environment, is the host's job. Stims does it with three.js on WebGL and WebGPU.

The CPU VM

compileMilkdropProgram gives you a function per program block; the loop that runs init, per-frame, per-pixel and the custom wave and shape programs in order, with the right register bank, and blends between presets, lives in Stims (vm.ts).

The GPU compute VM

Dispatching the WGSL this package generates and reading the state buffer back.

HLSL to WGSL

In Stims the shader text becomes WGSL through three.js TSL nodes, which this package does not depend on. The HLSL side here stops at the GLSL translation and the control analysis.

Semantics

The EEL2 semantics the interpreter, the JIT and the WGSL generator implement are specified by the sibling package eel-conformance (npm): portable JSON cases, a JSON Schema and a runner contract, which this package runs in its test suite. Five behaviours that differ from JavaScript and trip up most reimplementations:

  1. Division by exact zero yields 0, not Infinity or NaN (3 / 0 is 0).
  2. % truncates both operands to integers first, and a zero divisor yields 0.
  3. Truthiness is |v| > 0.00001: if(0.000001, a, b) takes the b branch.
  4. bor and band are logical, not bitwise: bor(0.5, 0) is 1.
  5. Identifiers are case-insensitive: Zoom, ZOOM and zoom are the same variable, and pi and e are ordinary prepopulated variables a preset may overwrite.

Try any of them in the scratchpad above.
